## User direction

First polish the existing system according to the project's philosophy: mechanisms
are general, instances and meaningful choices are profiles/data, expert controls are
complete. Preserve and extend current examples. A user should be able to point to
what they want changed from the keyboard. Long-press a tile to configure its details.
Launching the keyboard must collapse the shade and allow a shortcut session without
an editor. Model setup begins with what the user wants, including a specific model
when they have no provider account. Extend the phone with integrated media, password
and payment workflows, while making the platform's actual limits visible.

These instructions authorize continued implementation, not merely planning. Do not
convert every imaginable extension into a claim that it is implemented.

## Implemented in this change

* Expert settings: one searchable canonical schema, type/range/JSON validation,
  modified filter, per-option reset and precise numeric values. A reflection test
  holds every Settings property to the persistence codec.
* Ten versioned partial settings profiles, change previews, scoped save/export,
  validated merge/import and undo. Private payloads and credentials stay local.
* Offline contextual setting search (English and Polish aliases) and saved panels;
  model-assisted arrangement remains optional.
* 52 action instances moved out of IoPanel code into `action_profiles.json`.
  Stable-id overrides can rename, hide, replace or add instances. Long-press opens
  related settings. Destination validation shares the settings navigation catalogue.
* Keyboard toolbar independent of suggestions, persistent customization entry,
  pin/release control, contextual lock/model/media/vault access. MainActivity now
  processes new intents while already open instead of retaining its previous route.
* Shared tile collapse coordinator, proper Android 14 PendingIntent launch,
  long-press preferences routing, bounded shortcut sessions, temporary fieldless
  layout and explicit escape. Lock domains and fallback behavior are configurable.
* Capability/model-first provider discovery, documented routes and signup steps,
  provenance/freshness, Google Gemini Embedding 2 setup, embeddings parameters and
  explicit live smoke test. Provider-specific endpoint/key and capability parameters
  are used by actual adapters rather than saved into unrelated chat settings.
* SAF media hub: persistent user-selected local/cloud folders or files, unified
  listing, current-level search, MIME view profiles, open/share/copy and explicit
  offline/revoked/virtual/truncated states. No storage-wide permission is requested.
* Device-authenticated encrypted vault, standard login CSV import, password
  generation, app/browser selection, exact package/signer/HTTPS-origin binding and
  explicit authenticated Autofill choice. Cards omit CVV; supported text fields can
  be filled without submitting a form or authorizing a payment. Existing managers
  and wallet settings remain accessible through Android's own handoff.
* Settings encryption with Android Keystore and AtomicFile in no-backup storage,
  safe legacy migration, asynchronous coalesced writes and visible durability errors.
  Saved profile files also use atomic IO and preserve malformed originals.
* Private-form marker and password/data-sensitive node guards; private fields are
  excluded from learning, model context and macro recording. Provider credentials
  are excluded from logs and protected against cross-origin polling/redirects.
  Search/share cannot read private input. Revoking network control closes existing
  TCP clients and rejects already-queued commands from the old session.
* Matrix `local-only` remains a hard boundary even with an explicit transform.
  Provenance preserves simultaneous generated/inferred/external origins. Image
  reencoding retains RGB and dimensions and records alpha/quality loss.

## Explicit remaining scope

* No phone or emulator was connected for this change. Test notification-shade return,
  real editor focus, hardware keys, OEM overlays, Keystore unlock, browser Autofill
  and cloud-provider grants on a device before treating those paths as release-tested.
* Media integration covers installed Android DocumentsProviders and user grants.
  Direct OAuth adapters for providers without SAF, cloud-wide recursive indexing,
  offline synchronization and conflict handling remain extensions.
* The vault does not implement passkeys, cross-device recovery/synchronization,
  arbitrary other-manager database access, CVV storage or payment processing/NFC
  token provisioning. Its data is device-bound and requires an independent recovery
  strategy before it becomes a user's sole credential store.
* Provider discovery is bounded by configured evidence sources and account access.
  It does not claim every provider on the internet. No paid inference was run during
  development; the UI offers an explicit provider test.
* Abilities marked `built=false` remain unimplemented, including playback capture
  and background notifications. Do not request their permissions as if that alone
  implemented them. Add real adapters and tests behind the same capability model.
* Image reencoding covers static bitmap color/size. Complete HDR/high-bit-depth,
  animation and source-metadata preservation require richer representation profiles.
* Further profile extraction should retain the existing abstraction and runtime
  consumer, rather than creating a parallel registry which is never executed.

2. Extend media source profiles with direct provider adapters only where SAF cannot

3. Extend permission-backed capabilities through explicit event/source/transform/

   protocols; retain explicit target trust and user confirmation for every fill.
5. Continue the architecture audit for hidden policy constants and defaults. Security
